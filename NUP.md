# NUP Tools

NSP Box 4.0 introduces experimental NUP support with limited real-world testing.
The existing Game and DLC tabs still build NSPs as before.

## Operations

- **Folder → NUP:** choose an extracted snapshot, an update-only bundle, a DLC folder
  with its original title ID, or a `base/updates/dlc` bundle.
- **NSP → NUP:** import verified unsigned plaintext NSPs generated by NSP Box.
  Encrypted/retail NSPs and arbitrary NCA variants are refused. No keys are used.
- **NUP → Folder:** extract checked Base / Updates / DLC groups. File hashes are
  always checked. Existing files are never overwritten.
- **NUP → NSP:** reconstruct a game snapshot and export separate installable DLC NSPs.
  Check Base / Updates / DLC to choose the content to convert.
- **Inspect / Verify:** title IDs, kinds, versions, file counts, metadata types and
  compression statistics. Checked verification reads all file hashes; unchecked
  inspection validates structure and the table hash only.

Choose an operation directly from the button row; compression presets use buttons
too. Input paths can be typed (press Enter), browsed or dropped onto the tab. Source
inspection runs automatically after browsing/dropping. There is no separate Inspect
button or package dropdown. Inspect / Verify remains a dedicated operation.

Results are saved **beside the input**, without a destination dialog: `Game.nup`,
`Game-extracted/`, or `Game-NSP/`. Existing names get numbered copies, e.g.
`Game (2).nup`. For a folder source, the NUP sits next to the selected folder,
outside its contents. Open output takes you to the result. CLI output paths remain
explicit. Workers keep the UI responsive; Cancel removes unfinished outputs.

**Base / Updates / DLC** choices appear only after successful source inspection,
and only for content actually found in that source. Editing or clearing the source,
starting a new scan, or a failed scan hides old choices. A pasted path can be
inspected with Enter; Run inspects an unscanned source first so you can choose its
content before building. Available groups are checked by default on first use;
your checkbox preferences remain when switching sources. Hidden groups never enter
the output. Inspect / Verify has no output-selection controls.

These choices filter content **before** merging.
Unchecking Updates keeps the base snapshot; unchecking Base means no base fallback
files are added. An update-only conversion therefore requires a complete snapshot.
The smaller snapshot setting does not override these selections. With it off, selected
base/update records stay separate. The latest-snapshot option appears for folder
sources with updates; it is unnecessary for a base-only or DLC-only source. With
Base and Updates both selected, it creates **one merged game snapshot**, using the
newest update and keeping required base-only files. DLC remains separate in both modes. Inspect / Verify
checks the whole archive, independent of the inclusion checkboxes. Single-package CLI
selection (`--package-index`) remains available.

**Folder → NUP** reveals optional Title and Add cover controls with a reversible
layout animation. Add cover opens the existing square crop editor; Edit cover reopens
it, and Clear removes the override. Supported formats include WEBP, PNG, JPEG and more;
artwork can also be dropped onto this mode. The cropped cover and title override NUP
presentation metadata for selected game records (or DLC when packing DLC alone).
Original filesystem contents, title IDs and NPDM remain unchanged. NUP → NSP uses
these game presentation overrides when reconstructing control metadata. Extended
NACP title layouts that the app cannot safely edit retain their original NACP;
the NUP title field still changes. Leaving both blank
retains detected metadata. A game bundle's custom title/cover does not rename its DLC.

NSP inspection reads the index, headers and metadata, without hashing the full game.
Source integrity is checked when converting. Folder packing reuses its inspected
index instead of walking it twice; changes to source files/folders invalidate it.
Indexing also reports a file count so a large scan is visibly progressing.

## Compression and space

Fast = Zstandard **1**, Balanced = **3** (default), Smaller = **9**. Per-file results
that do not reduce size are stored raw. Identical files share one extent across
packages. Empty files/directories are retained. `.listing` dump artifacts are excluded
from folder packaging; imported NSP files are preserved as they were.

**Keep files > 256 MiB raw** is on by default. The checked Eglantine NUP reader may
decompress large compressed files to temporary disk storage. Disabling the option
may save archive space but increase emulator launch time and temporary disk use.
Files are streamed in 1 MiB blocks; incompressible files are re-read for raw storage.
Folder/NSP → NUP does not stage a whole-game copy. Plausible duplicates are fully
hashed before compression, and exact duplicates reuse their stored extent. A short
prefix is only a screening hint; it never establishes equality. Verification reads
each unique stored extent once and validates every file's reference to it.
The size comparison includes container overhead, so very small inputs may grow.
Space is reserved conservatively for a raw worst-case archive.

NUP → NSP uses temporary extracted data plus its output (approximately 2.1× selected
uncompressed bytes plus metadata). Temporary data is cleaned up on completion or
cancellation. Multi-output conversion commits the completed folder together.

## Bundles and update handling

```
Game/
  base/exefs/ ...
  base/romfs/ ...
  updates/65536/exefs/ ...
  updates/65536/romfs/ ...
  dlc/0400........1001/0/romfs/ ...
```

NUP v1 carries file trees, not encrypted console delta NCAs. An empty base folder is
skipped; all updates in a base-less archive get the standalone flag. Title IDs come
from NPDM or the original DLC folder name; numeric versions come from folders/CNMT.
Unrelated IDs and duplicate package identities are refused.

**Keep latest game snapshot only (smaller)** is on by default for Folder → NUP.
It uses the latest update's ExeFS and merges that update over base RomFS, retaining
base-only files. The result has one game snapshot plus separate DLC records, rather
than storing obsolete game versions. Matching files are kept only in their updated
form. NPDM and build-ID metadata come from the selected executable. This does not
delete any source files. Turn the option off to preserve all base/update packages.

An `exefs/main` executable alone does not prove that its update RomFS is complete.
If you have tested a standalone update and want **only that update's files**, select
its `updates/<version>` folder directly. Selecting the main game folder retains
base-only fallback files. There is no filename-based rule that discards all base data.

Whole-archive NSP conversion follows the checked Eglantine loader:

1. Select the highest numeric update (or the chosen update).
2. Use its entire ExeFS when it supplies an executable, otherwise the base ExeFS.
3. Recursively overlay that update's RomFS onto the base; update files shadow base files.
4. Produce a base-application snapshot NSP and separate DLC NSPs.

Lower updates are not cumulatively overlaid. Selecting a base exports the unupdated
base; selecting an update merges it with the available base. A standalone update
must supply complete ExeFS/RomFS. Delta-only, ambiguous, unrelated or conflicting
file/directory content is refused. The tool cannot infer whether all files needed
by an actual game were dumped. With archive-all mode, older update records remain
in the NUP and can be separately selected for extraction/conversion. DLC is never merged into the
game RomFS. A game plus DLC requires a new output folder for multiple NSP files.

## Metadata and emulator limits

NPDM, original NACP, icons and filesystem files are preserved byte-for-byte, along
with title IDs and numeric versions. NSP reconstruction regenerates unsigned NCA/CNMT
hashes; its container is not byte-identical to the original. Imported CNMT bytes are
also retained as `data/nsp/` in NUP. Minimal NACP is generated only when none exists.
Unknown NUP metadata TLVs survive extraction in `nup-manifest.json`; keep this beside
the extracted package folders for repacking. An extracted update-only selection is
correctly marked standalone on repacking.

When merging an update, the original base control record remains unchanged, so its
human-readable display version can still reflect the base; the reconstructed CNMT
uses the selected update's numeric version.

The checked Eglantine loader selects/overlays NUP updates but explicitly does **not
mount NUP add-ons in-game yet**. Archiving DLC does not add emulator DLC support.
Convert DLC to a separate NSP and install it through a compatible emulator. NUP
playback requires an emulator build with NUP support; the NSP patch does not add it.
Synthetic checks do not establish game booting, FPS or DLC recognition. Keep originals.

The previous “Frame requires too much memory for decoding” bug came from the
backend enforcing a decoder-window setting in bytes. The corrected reader accepts
valid writer-produced frames above the old 1 MiB cap, with a 1 GiB maximum window.
It still streams output and checks declared lengths and hashes; it does not load
the entire uncompressed file into RAM. Completed valid NUPs do not need repacking
solely for this decoder fix.

## Large games

There is **no 32 GiB application cap** for NSP or NUP payloads in this preview.
NSP/PFS0 uses 64-bit file offsets/sizes; its NCAs use 32-bit 512-byte sector offsets,
so each generated NCA must remain below approximately **2 TiB**, including integrity
data. NUP uses 64-bit payload offsets/sizes; its separate metadata table is bounded
at 256 MiB and 4096 packages. These metadata bounds are not a game-size limit.
Free disk space, a 64-bit runtime and destination-filesystem limits still apply.
In particular, FAT32 cannot hold a single file of 4 GiB or more.

Structural tests exercise 40/96 GiB NSP headers and a virtual 40 GiB NUP without
creating huge output files. A full real-game conversion above 32 GiB has not yet
been performed in this environment. Large-file arithmetic and bounded streaming
are checked; an individual emulator may impose additional limits.
